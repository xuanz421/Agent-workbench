# DESIGN.md

Project-local UI and visual design guidance.

> This file should describe the target project's actual design language. It is not a global Agent-Workbench rule set.

## Product / UI Intent

Describe the primary users, tasks, information density, and interaction priorities.

## Visual Direction

Document the intended visual character and any explicit constraints.

## Color Roles

Define semantic roles rather than isolated hex values when possible.

- Background
- Surface
- Primary
- Secondary
- Accent
- Text
- Muted text
- Border
- Success
- Warning
- Error

## Typography

- Font families
- Heading scale
- Body scale
- Weight usage
- Line-height conventions

## Spacing

Document the spacing scale and page/component rhythm.

## Radius / Elevation

Document border radius, shadows, overlays, and surface hierarchy.

## Layout Rules

- Content widths
- Page gutters
- Grid behavior
- Section spacing
- Navigation layout

## Components

Document reusable component expectations and variants.

- Buttons
- Inputs
- Cards / surfaces
- Navigation
- Tables / lists
- Dialogs
- Feedback states

## Interaction States

Define hover, focus, active, selected, disabled, loading, success, empty, and error behavior where relevant.

## Responsive Rules

Document breakpoints, collapsing behavior, mobile priorities, and overflow handling.

## Accessibility

Document required contrast, keyboard, focus, labels, semantic structure, reduced-motion, and other project expectations.

## Known Exceptions

Record intentional deviations from the normal system.

## Decision Status

When useful, distinguish:

- Confirmed existing rule
- Strong repeated pattern
- Newly proposed baseline
- Local exception
- Unknown / requires validation
