# WorldBox 模组实机测试

优先复用项目已有的游戏测试脚本与进程内探针。此技能处理“怎样让真实游戏执行验证并取得证据”，不替代项目的玩法规格，不把某个模组的参数当作游戏通用参数。

## 先确认环境与边界

1. 阅读项目 `AGENTS.md`、构建配置、实际测试入口和公共启动脚本。确认仓库、游戏版本、NML、`worldbox.exe`、测试模组目录及报告输出位置。路径从当前配置解析并核对存在，不依赖历史聊天中的盘符。
2. 确认是可覆盖的专用测试实例，且与用户正式模组、存档及发行副本分离。首次使用不明目录时先确认用途；备份放在 `mods` 之外，避免相同 GUID 被重复加载。
3. 检查是否已有 WorldBox 进程；有用户进程时停下并请用户关闭，不按进程名批量结束游戏，不自行接管用户存档。
4. 识别请求范围，选择最小有效验证：隔离逻辑回归、真实世界交互、设置／日志专项、完整界面或自然长局。仅整理技能或方法时，不为了验证文档而启动游戏、修改模组。

具体模式、参数、加载钩子与归档路径从目标项目本地文档和当前脚本获取。项目专用配方应留在对应仓库；不要把某个模组的命令行协议或固定盘符复制给其他项目。

## 准备测试源码

- 先构建，失败则停止并保留输出。对 NML 源码模组，`dotnet build` 仅证明编译与引用成立；实际代码由游戏启动时重新编译，不能把构建出的 DLL 当作已加载证据。
- 复用项目同步脚本，核对实际目标后只更新测试模组。重排或移动过源码时清理测试副本中的过期源码，避免旧类、旧补丁仍参与编译；递归操作仅允许已验证的模组子目录。
- 测试夹具用项目已有的开发条件符号和命令行显式启用，正式版本不带测试入口、临时补丁或验收计数器。不要用玩家设置开关常驻测试。
- 核对源文件、资源、配置及唯一模组标识；测试修改不要外溢到中文／英文发布副本。测试授权不包含正式同步、发布、Git 提交或推送。

## 调用游戏

- 优先运行已存在的外围脚本，不另造一套重复启动器。核对它确实设置游戏工作目录、独立运行标识、报告和日志路径、超时与清理。
- 需要新启动实现时，使用完整可执行路径和 `Start-Process -PassThru`，路径参数按空格正确引用；默认 `-WindowStyle Hidden`。仅截图或交互测试确实需要渲染窗口时显示本次测试窗口。
- Unity 日志可用已核对支持的 `-logFile`；自定义测试参数必须由当前模组源码显式解析。游戏本身不会因为传入一个未知参数就执行测试。
- 由进程内探针调用真实 API、跨帧等待加载、年度变化和窗口动画。普通隔离夹具只覆盖确定性逻辑；涉及城市归属、真实生产或完整存读档时需要相应实机消费点，不能用手工写入字段代替整个自然过程。
- 有界等待报告、进程退出或超时；长任务通过工具返回的会话继续轮询，并及时向用户更新。提前退出、无报告、加载异常或超时都不得计作通过。
- `finally` 中只清理本次启动并持有对象的进程：先正常关窗，有限等待后才终止该进程。不要调用全局 `Stop-Process -Name worldbox`。

## 读取报告与看图

- 先看外围退出码，再按报告实际格式统计 `PASS`、`INFO`、`FAIL`。没有表头的 TSV 按行解析，不把第一条结果误当表头；异常堆栈行不是额外测试项。
- 报告存在不等于完成。核对写出时机、预期检查项和末阶段；缺项、未完成或格式损坏单独报告。预期项数来自当前探针，不硬编码某次历史运行的总数。
- `INFO`、条件跳过和未测项不折算成 `PASS`。专项通过不冒充整轮全绿；原失败与新复测分别记录，重试通过不能证明间歇性问题根因已解决。
- 检查游戏日志中的编译、初始化、Harmony 目标及运行异常。定位模组自身问题，只修用户授权范围；原版游戏问题先区分责任，不自动修补游戏。
- 截图要等实际窗口／悬浮内容稳定且文件完成写出，核对标题、语言、尺寸、目标图标及页面状态。文件非空只是最低检查；用图像查看工具实际检查代表截图。
- 标明实际渲染分辨率及是否来自受控测试世界。主菜单动画背景、遗留窗口或拍错目标不是有效玩法展示；资源拼图、界面模拟不能称为实机截图。
- UI 直接操作时，按可用的电脑操作技能选定真实窗口；探针式测试不依赖桌面点击。工具不可用时不能虚构点击或截图结果。

## 交付与失败处理

汇报运行模式、游戏版本、退出码、原始计数、报告／日志／代表截图路径，以及未测边界。需要存档验收时核对完整世界重载后的原 ID、归属与持久数据；自然发展速度不能由受控授予推算成实机结论。

失败保留原始报告和日志，找到最早错误状态再决定是否做一次有依据的复测；同样失败反复出现时不要无限重跑。修复需要额外范围时先向用户说明。

证据按项目口径归档：完整原件与 SHA256 保留，历史摘要留下原始计数、诊断与失败堆栈，不为每次运行重复提交全部 PASS。失败运行不覆盖最后全绿基准；临时诊断补丁用完恢复，仅由正式测试维护的夹具可留在开发目录。
